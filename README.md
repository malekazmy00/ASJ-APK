# ASJ Medical Systems Store — Flutter

## ملاحظة تقنية مهمة (Codemagic)
المشروع مكتوب يدوياً بدون تشغيل `flutter create` فعلياً (لا توجد بيئة Flutter في هذه الجلسة)، فمجلد `android/` غير موجود في الزيب. `codemagic.yaml` بيولّده تلقائياً كخطوة أولى قبل البناء (ويضيف صلاحية الكاميرا للمانيفست تلقائياً كمان) — خطوة قياسية آمنة، لكنها **لم تُختبر حياً**. لو فشلت في أول Build فعلي، ابعتلي رسالة الخطأ من Codemagic فوراً.

## الحالة الحالية (بعد اكتمال المراحل 1-4 + جزء كبير من الصور)
- **المرحلة 1 (الأساس)**: ✅ مكتملة.
- **المرحلة 2 (شاشات الأدوار)**: 🟡 الأساسي + دفتر استعلامات المهندس جاهزين. ناقص: تعديل قاعدة المعرفة المباشر عند المهندس، واستيراد CSV + الإحصائيات عند الأدمن (راجع PROJECT_PLAN.md §7.1).
- **المرحلة 3 (تتبع القطعة/المستخدمين + الداشبورد التجميعي)**: ✅ مكتملة، 3 تبويبات جديدة في لوحة الأدمن.
- **المرحلة 4 (Edge Functions)**: ✅ مكتملة (login-user، analyze-part، admin-create-user).
- **الصور**: 🟡 التقاط/اختيار الصورة + إرسالها لتحليل الذكاء الاصطناعي **شغال الآن** عند العامل. الحفظ الدائم للصورة على Supabase Storage لسه مؤجل (راجع PROJECT_PLAN.md §7.2).

## خطوات لازم تتعمل بالترتيب قبل أول تجربة

### 1) قاعدة البيانات
شغّل `supabase/migrations/001_pending_and_new_tables.sql` كامل في SQL Editor على Supabase (بيضيف `serial_number`، جدول `user_sessions`، و View التجميع).

### 2) نشر الـ Edge Functions (بدون أي جهاز/Terminal)
من لوحة Supabase مباشرة:
1. روح لقسم **Edge Functions** في لوحة Supabase.
2. أنشئ دالة جديدة اسمها بالظبط `login-user`، وحط فيها محتوى `supabase/functions/login-user/index.ts`.
3. كرر نفس الخطوة لـ `analyze-part` و `admin-create-user`.
4. من (Project Settings > Edge Functions > Secrets)، أضف `GEMINI_API_KEY` بمفتاحك.
   (`SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` بتتوفر تلقائياً.)

### 3) بناء أول APK
1. ارفع محتوى هذا المجلد على GitHub.
2. اربط الريبو بـ Codemagic (`codemagic.yaml` جاهز، بيولّد `android/` تلقائياً).
3. أضف Environment variable group باسم `supabase` فيها `SUPABASE_URL` و `SUPABASE_ANON_KEY`.
4. شغّل الـ Build ونزّل الـ APK.

### 4) أول اختبار حي — بالترتيب المقترح
1. تسجيل الدخول بمستخدم موجود بالفعل في جدول `users`.
2. واجهة العامل: التقط صورة قطعة (أو اكتب رقمها) واضغط "تحليل بالذكاء الاصطناعي"، وتأكد إن الرد بييجي صح.
3. احفظ القطعة وتأكد إنها ظهرت في `inventory_items`.
4. واجهة المهندس: ابحث عن نفس القطعة، جرّب الصرف، وسجّل استعلام تجريبي في "دفتر الاستعلامات".
5. لوحة الأدمن: تأكد من ظهور المستخدمين، ثم افتح تبويب "المخزون" (الداشبورد التجميعي)، و"تتبع قطعة" (اكتب نفس رقم القطعة اللي جربتها) و"تتبع مستخدم" (اكتب اسمك وشوف الجلسة اللي فتحتها بالدخول).

**مهم:** لو أي خطوة فشلت، ابعتلي رسالة الخطأ بالظبط (SnackBar في التطبيق أو Logs الخاصة بالـ Edge Function في لوحة Supabase) وهنشخصها فوراً.

## الباقي (بعد أول تجربة ناجحة)
- تعديل قاعدة المعرفة المباشر عند المهندس.
- استيراد CSV والإحصائيات عند الأدمن.
- حفظ الصورة بشكل دائم على Supabase Storage.

## التجربة على قاعدة بيانات اختبار منفصلة (بدون لمس بيانات العمل الفعلية)
**لا تجرب على مشروع Supabase الحالي اللي عليه بيانات حقيقية.** اعمل مشروع Supabase جديد فاضي مخصص للتجربة فقط (فري تير كافي)، وخطوات ربطه:

### 1) إنشاء قاعدة الاختبار
افتح SQL Editor في مشروع Supabase **الجديد** (الاختباري)، والصق محتوى `supabase/schema_test_db.sql` كامل وشغّله مرة واحدة — بينشئ كل الجداول والفهارس من الصفر مطابقة تماماً لبنية الإنتاج.

### 2) نشر نفس الـ Edge Functions
نفس خطوات README الأساسية (`login-user`، `analyze-part`، `admin-create-user`) بس على مشروع الاختبار ده، مش الإنتاج.

### 3) تجهيز أول مستخدم اختبار (مشكلة الدجاجة والبيضة)
قاعدة الاختبار فاضية من المستخدمين، وإنشاء مستخدم من داخل التطبيق محتاج أدمن مسجل دخول بالفعل — يعني محتاج نبعت أول طلب لدالة `admin-create-user` من برة التطبيق:
1. افتح موقع اختبار طلبات مجاني من المتصفح زي `reqbin.com` (شغّال من الموبايل مباشرة، من غير تحميل أي حاجة).
2. اختار طلب POST، والرابط: `https://<project-ref>.supabase.co/functions/v1/admin-create-user` (لاقي `project-ref` في رابط مشروع الاختبار).
3. في الـ Headers ضيف: `Authorization: Bearer <anon key بتاع مشروع الاختبار>` و `Content-Type: application/json`.
4. في الـ Body (JSON): `{"username": "test_admin", "password": "Test1234", "role": "admin", "can_export": true, "can_track": true, "can_edit": true}`.
5. ابعت الطلب — لو رجع `{"success": true}`، تمام، عندك أول مستخدم اختبار.

بعد كده أي مستخدم إضافي تقدر تعمله عادي من داخل التطبيق (لوحة الأدمن).

### 4) توجيه التطبيق لقاعدة الاختبار
في Codemagic، غيّر قيم `SUPABASE_URL` و `SUPABASE_ANON_KEY` في مجموعة `supabase` لتبقى بيانات مشروع **الاختبار** بدل الإنتاج، واعمل Build. جرّب براحتك من غير أي قلق على البيانات الحقيقية.

### 5) الرجوع للإنتاج
لما تطمّن وتبقى قرّبت تعتمد النسخة، رجّع قيم `SUPABASE_URL` و `SUPABASE_ANON_KEY` لبيانات مشروع الإنتاج الحقيقي واعمل Build نهائي. مفيش أي تعديل كود مطلوب — ده بالظبط سبب استخدام `--dart-define` بدل كتابة الروابط في الكود مباشرة.
